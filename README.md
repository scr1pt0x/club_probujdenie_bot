# Клуб «Пробуждение» — Telegram-бот

Бот управляет участием в онлайн-клубе: оплатой через YooKassa, доступом в
Telegram-канал и группу, потоками, отсрочкой «Оплачу позже», промокодами,
рассылками и администрированием внутри Telegram.

## Основные возможности

- персональный расчёт стоимости: вступление или непрерывное продление;
- создание и повторная проверка платежа YooKassa;
- автоматическая выдача ссылок на канал и группу после оплаты;
- проверка заявок на вступление по действующему участию;
- платные потоки длительностью 5 недель и опциональные бесплатные потоки;
- отсрочка «Оплачу позже» с напоминаниями и контролем дедлайна;
- промокоды: процент, фиксированная скидка или бесплатное участие;
- сегментированные и автоматические рассылки;
- Telegram-админка для потоков, цен, текстов, пользователей и рассылок;
- `/api/healthz` для проверки приложения и соединения с PostgreSQL.

## Требования

- Python 3.10+
- PostgreSQL 14+
- бот с правами администратора в целевом канале и группе
- учётная запись и ключ API YooKassa

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
alembic upgrade head
python main.py
```

Заполните в `.env` как минимум:

- `BOT_TOKEN`
- `DATABASE_URL`
- `PRIMARY_CHANNEL_ID`
- `SECONDARY_DISCUSSION_ID`
- `ADMIN_TG_IDS`
- `YOO_KASSA_SHOP_ID`
- `YOO_KASSA_SECRET_KEY`

Секреты хранятся только в `.env`; файл исключён из Git.

## Пользовательский интерфейс

- `/start` открывает компактное inline-меню;
- каждый переход заменяет предыдущий экран вместо отправки цепочки сообщений;
- создание счёта и включение «Оплачу позже» требуют явного подтверждения;
- `👤 Мой доступ` показывает срок участия и доступность отсрочки;
- `✨ Участие` показывает условия и персональный переход к оплате;
- `🗓 Расписание`, `🏷 Промокод` и `💬 Помощь` доступны из того же экрана.

Старые reply-кнопки продолжают обрабатываться для совместимости, после первого
нажатия они удаляются и заменяются новым интерфейсом.

Админ-панель открывается командой `/admin` только для Telegram ID из
`ADMIN_TG_IDS`.

## Продакшен

Приложение одновременно запускает Telegram polling, планировщик APScheduler и
FastAPI на `127.0.0.1:8000`. Внешний Nginx должен проксировать `/api/` на этот
порт. Рекомендуемый порядок выпуска:

1. сделать резервную копию PostgreSQL;
2. обновить код без перезаписи серверного `.env` и локальных служебных файлов;
3. установить зависимости и выполнить `alembic upgrade head`;
4. перезапустить systemd-сервис;
5. проверить `/api/healthz`, журнал сервиса и Telegram polling.

`REVOKE_JOBS_ENABLED=false` оставляет автоматическое удаление участников
выключенным. Включайте его только после dry-run проверки данных и значения
`MAX_REVOKE_PER_RUN`.

Автоматическое исключение выполняется только одним заданием после завершения
grace-периода. Перед обращением к Telegram бот блокирует запись пользователя и
повторно проверяет все активные участия и оплаченные будущие потоки. Успешные
автоматические исключения записываются в журнал администратора.

Для участниц с постоянным или льготным доступом администратор может включить
защиту в карточке пользователя. Такая участница не исключается фоновыми
заданиями и не попадает в список ручной сверки Telegram-доступа.

Разовая сверка пользователей, которые остались в Telegram после завершения
участия:

```bash
python scripts/reconcile_telegram_access.py
python scripts/reconcile_telegram_access.py --apply --limit 30
```

Первая команда всегда работает в режиме dry-run. Скрипт защищает настроенных
администраторов, текущие участия и будущие оплаченные потоки.
